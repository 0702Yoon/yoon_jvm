## GC 기본 개념

### 가비지 컬렉션이란?

가비지 컬렉션(Garbage Collection)은 더 이상 사용되지 않는 객체를 자동으로 찾아

**메모리**를 **회수하는** 메커니즘입니다.

**핵심 질문**: 어떤 객체가 "더 이상 사용되지 않는" 객체인가?

**답**: GC Root에서 도달할 수 없는 객체

### GC Root란?

GC Root는 가비지 컬렉션의 시작점이 되는 참조들입니다.

**YoonJVM에서의 GC Root**:

- JVM Stack의 모든 Frame에 있는 지역 변수 (`Map<String, JVMObject>`)

> **실제 JVM의 GC Root**:
>
- Stack의 지역 변수
- Static 필드
- JNI 참조
- 동기화 모니터
- 클래스 로더 참조

GC루트에 대한 자세한 내용은 가상 머신 스택에서!

---

### Reachability (도달 가능성)

```
GC Root
  ├─> Object A (Reachable)
  │     └─> Object B (Reachable)
  │           └─> Object C (Reachable)
  │
  └─> Object D (Reachable)

Object E (Unreachable) ← GC 대상!
  └─> Object F (Unreachable) ← GC 대상!

```

GC Root에서 참조 체인을 따라 도달할 수 있으면 **살아있는(live)** 객체, 도달할 수 없으면 **가비지**입니다.

<aside>

살아있는 객체인 지 판단하는 또다른 방식인 객체 참조 카운팅 방식도 존재한다.

하지만 순환 참조 객체들이 동시에 null이 될 경우

도달할 수 없는 객체임에도 참조 카운팅이 0이 아니여서 메모리에서 해제되지 못하는 단점이 있다.

</aside>

> **자바는 도달 가능성 분석 알고리즘을 사용한다.**
>

### GarbageCollector 클래스 구조

```java
public class GarbageCollector {
    private static final int PROMOTION_AGE_THRESHOLD = 3;  // Old로 승격 기준 나이

    private final YoungGeneration youngGen;
    private final OldGeneration oldGen;
    private final JVMStack stack;

    private int minorGCCount;  // Minor GC 실행 횟수
    private int majorGCCount;  // Major GC 실행 횟수

    public int minorGC() { ... }      // Young Generation 정리
    public void majorGC() { ... }     // Old Generation 정리
    public void fullGC() { ... }      // 전체 힙 정리
}

```

**주요 상수**:

- `PROMOTION_AGE_THRESHOLD = 3`: 객체가 3번의 GC에서 살아남으면 Old Generation으로 승격

### Minor GC vs Major GC 비교

| 구분 | Minor GC | Major GC |
| --- | --- | --- |
| **대상** | Young Generation | Old Generation |
| **알고리즘** | Mark-and-Copy | Mark-and-Compact |
| **빈도** | 매우 자주 | 드물게 |
| **속도** | 빠름 (살아남은 객체 적음) | 느림 (살아남은 객체 많음) |
| **Survivor 교체** | 있음 | 없음 |
| **승격** | age >= 3 객체 → Old | 없음 |

## 8. 실제 JVM과의 비교

| 항목 | YoonJVM | 실제 JVM (HotSpot) |
| --- | --- | --- |
| **Young 영역** | Eden + S0 + S1 | Eden + S0 + S1 (동일) |
| **승격 기준** | age >= 3 (고정) | 적응형 (Adaptive Threshold) |
| **Remembered Set** | `Set<JVMObject>` | Card Table (바이트 배열) |
| **GC 알고리즘** | Mark-and-Copy, Compact | G1 GC, ZGC, Shenandoah 등 |
| **동시성** | Stop-the-World만 | Concurrent GC 지원 |

## 📚 핵심 학습 포인트

### ✅ GC의 핵심 개념

1. **GC Root**: 가비지 컬렉션의 시작점
2. **Reachability**: Root에서 도달 가능하면 살아있음
3. **Mark-and-Copy**: Young Gen (살아남은 객체 복사)
4. **Mark-and-Compact**: Old Gen (압축으로 단편화 방지)

### ✅ Remembered Set의 역할

- Old → Young 참조를 추적
- Minor GC 시 Old 전체를 스캔하지 않아도 됨
- Write Barrier로 참조 추가 시 자동 기록

### ✅ 객체 승격 메커니즘

- 나이(age) 기반: GC에서 살아남을 때마다 +1
- age >= 3이면 Old로 이동
- 장수 객체를 Old로 분리하여 Minor GC 효율 향상

### ✅ 자동 GC 트리거

- Eden 70% → Minor GC
- Old 80% → Major GC
- 적절한 임계값으로 메모리 압박 완화
