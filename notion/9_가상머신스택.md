### 자바 가상 머신 스택

- 자바 가상 머신 스택은 스레드 프라이빗하며, 연결된 스레드와 운명을 같이 한다.
    - 스레드 프라이빗: 스레드별로 독립적이다.
- 각 메서드가 호출될 때마다 자바 가상 머신은 **스택 프레임**을 만들고 가상 머신 스택에 푸쉬하고 메서드가 끝나면  POP하여 반환값을 반환한다.
    - **스택 프레임의 구조**
        - **지역 변수 테이블**
        - 피연산자 스택
        - 동적 링크
        - 메서드 반환값등

### **지역 변수 테이블**

자바 가상 머신이 컴파일타임에 알 수 있는 다양한 기본 데이터 타입, 객체 참조, 반환 주소 타입을 저장한다.

- 기본 데이터 타입: boolean, byte, char, short, int..
    - 테이터 타입들을 저장하는 공간을 **지역 변수 슬롯이라 한다.**
    - 슬롯 하나의 크기는 32비트로, double 타입처럼 길이가 64비트면 2개의 슬롯을 차지한다.
- 객체 참조: 참조 타입과 객체 자체는 다르다. 참조 타입은 객체의 시작 주소를 가리키는 참조 포인터일 수 있고, 객체를 대표하는 핸들 또는 객체와 관련된 다른 위치를 가리킬 수도 있다.
- 반환 주소 타입: 바이트코드 명령어의 주소 ( 메서드가 끝나고 돌아갈 주소)

→ 지역 변수 테이블을 구성하는 데 필요한 데이터 공간은 컴파일 과정에서 할당된다.

<aside>

즉 자바 메서드는 스택 프레임에서 지역 변수용으로 할당받아야 할 공간의 크기가 이미 완벽하게 결정되어있다는 뜻이다.

</aside>

**Local Variable Table의 인덱싱**:

지역 변수 섹션은 0 기반 배열로 구성되며, 인스턴스 메서드 호출 시 지역 변수 0은 항상 객체 참조(this)를 전달하는 데 사용되고, 파라미터는 지역 변수 1부터 차례로 전달된다.

### Frame 클래스 구조 -YoonJVM 구현

**YoonJVM의 단순화**:

- Local Variable Table만 구현 (Operand Stack 생략)
- Frame Data 생략 (메서드 이름만 저장)

```java
public class Frame {
    private final String methodName;                    // 메서드 이름
    private final Map<String, JVMObject> localVariables; // 지역 변수 테이블
    private final int maxLocals;                        // 최대 지역 변수 개수

    public Frame(String methodName, int maxLocals) {
        this.methodName = methodName;
        this.maxLocals = maxLocals;
        this.localVariables = new HashMap<>();
    }
}

```

### GC Root의 종류

**실제 JVM의 GC Root 타입**:

> 가비지 컬렉션 루트는 힙 외부에서 접근 가능한 객체입니다. GC Root는 추적 수집기의 시작점입니다.
>

**주요 GC Root 타입**:

1. Stack Local Variables
    - 스레드 스택에 여전히 남아있는 메서드의 지역 변수, 입력 파라미터, 또는 로컬로 생성된 객체들
2. **Static Fields**
    - 정적 변수는 클래스에 의해 참조되므로 사실상 GC Root입니다. 시스템 클래스 로더에 의해 로드된 클래스는 정적 필드를 통해 객체를 보유할 수 있습니다.
3. **Active Threads**
    - 활성 Java 스레드는 항상 살아있는 객체로 간주되므로 GC Root입니다.
4. **JNI References**
    - JNI 참조는 네이티브 코드가 JNI 호출의 일부로 생성한 Java 객체이며, JVM은 네이티브 코드가 이를 참조하는지 알 수 없으므로 특별히 처리됩니다.
5. **Synchronization Monitors**
    - `wait()` 또는 `notify()`를 호출했거나 `synchronized`된 모든 것

**GC Root의 역할**:

```
GC Roots:
- Stack Local Variables (Thread 1, 2, 3...)
- Static Fields (ClassA.staticField, ClassB.staticField...)
- JNI References
- Active Threads
    ↓ 참조 체인 추적
[Reachable Objects]
    ↓
모든 도달 가능 객체 마킹
    ↓
나머지는 가비지 → 수집!

```

## 실제 JVM과의 비교

### 6.1 Frame 구조 비교

| 항목 | YoonJVM | 실제 JVM (HotSpot) |
| --- | --- | --- |
| **Local Variables** | `Map<String, JVMObject>` | `int[]` (인덱스 기반) |
| **Operand Stack** | 없음 | `Object[]` (LIFO) |
| **Frame Data** | methodName만 | 상수 풀, 예외 테이블, 반환 주소 |
| **this 참조** | 명시적 저장 필요 | local[0] 자동 할당 |

### 6.2 JVMStack 비교

| 항목 | YoonJVM | 실제 JVM |
| --- | --- | --- |
| **스레드당 스택** | 1개 (단일 스레드) | 각 스레드마다 1개 |
| **최대 깊이** | 10 (교육용) | 수천~수만 (조정 가능) |
| **자료구조** | `Stack<Frame>` | 연속 메모리 블록 |
| **GC Root** | 모든 Frame | 모든 Frame |

### 6.3 GC Root 비교

| GC Root 타입 | YoonJVM | 실제 JVM |
| --- | --- | --- |
| **Stack Locals** | 지원 | 지원 |
| **Static Fields** | 미지원 | 지원 |
| **JNI References** | 미지원 | 지원 |
| **Active Threads** | 미지원 | 지원 |
| **Monitors** | 미지원 | 지원 |
