### 계층별 구현 내역

### 1. Foundation Layer (기본 데이터 구조)

**완료 항목**:

- [x]  `JVMClass`: 클래스 메타데이터 (매직 넘버, 버전, 필드)
- [x]  `JVMObject`: 런타임 객체 (헤더, 데이터, GC 정보)
- [x]  `ClassFileVersion`: Java 버전 관리 (1.1 ~ 17)

---

### 2. Memory Layer (런타임 메모리 구조)

**완료 항목**:

- [x]  `RunTimeMemory`: 전체 메모리 통합 관리
- [x]  `YoungGeneration`: Eden + Survivor0 + Survivor1
- [x]  `OldGeneration`: 구세대 메모리
- [x]  자동 대형 객체 승격 (Young의 50% 초과 시) → **신세대 남은 메모리 양을 기준으로 자동 승격**
- [x]  Survivor 교체 메커니즘 (swapSurvivors)

---

### 3. Runtime Stack Layer (런타임 스택)

**완료 항목**:

- [x]  `Frame`: 메서드 호출 프레임 (지역 변수 테이블)
- [x]  `JVMStack`: 프레임 스택 관리 (push, pop)
- [x]  GC Root 수집: main 프레임의 지역 변수

---

### 4. GC Layer (가비지 컬렉션)

**완료 항목**:

- [x]  `GarbageCollector`: Minor/Major/Full GC 구현
- [x]  `ReferenceTracker`: Old→Young 참조 추적 (Card Table)
- [x]  Minor GC (Mark-and-Copy): Young Generation GC
- [x]  Major GC (Mark-and-Compact): Old Generation GC
- [x]  나이 기반 승격 (age >= 3)
- [x]  자동 GC 트리거 (Eden 70%, Old 80%)

---

### 핵심 교훈

**복잡한 시스템도 단순한 원칙의 조합이다**

JVM은 복잡해 보이지만, 다음 원칙으로 이해 가능:

- **Weak Generational Hypothesis** → Young/Old 분리
- **Reachability** → Mark Phase
- **Copy** → 메모리 단편화 제거
- **Age** → 승격 메커니즘
- **Card Table** → 효율적인 Minor GC

## 🎓 학습 회고

### 프로젝트를 마치며

이번 YoonJVM 프로젝트를 통해 JVM의 메모리 관리와 가비지 컬렉션의 핵심 원리를 직접 구현하며 깊이 이해할 수 있었습니다.

**학습 목표 달성:**

- **Generational GC의 동작 원리 완벽 이해**: Young/Old Generation의 분리 이유와 각각의 GC 알고리즘을 코드로 구현하며 체득
- **Mark-and-Copy vs Mark-and-Compact**: 이론으로만 알던 두 알고리즘의 차이를 직접 구현하며 명확히 이해
- **객체 생명주기 추적**: Eden → Survivor → Old로 이어지는 객체의 여정을 코드로 표현
- **참조 추적 메커니즘**: GC Root부터 시작하는 Reachability 분석을 재귀적으로 구현
- **Card Table 원리 체득**: Old→Young 참조 추적을 위한 ReferenceTracker 구현으로 실제 JVM의 최적화 기법 이해

**특히 만족스러웠던 부분:**

1. **계층별 설계**: Foundation → Memory → Runtime → GC로 이어지는 명확한 아키텍처 구성
2. **실제 JVM 반영**: 단순한 시뮬레이터를 넘어 실제 JVM의 동작 원리를 최대한 반영
3. **자동화 로직**: Eden 70% 초과 시 자동 Minor GC, 대형 객체 자동 승격 등 실전적인 기능 구현

**기술적 성장:**

- 복잡한 시스템을 작은 단위로 분해하고 조립하는 능력 향상
- 메모리 관리의 trade-off를 직접 경험 (속도 vs 메모리 효율)
- 참조 관계 추적과 순환 참조 처리 능력 습득
- 디자인 패턴 실전 적용 (Handler Pattern, Strategy Pattern)

**아쉬운 점과 개선 방향:**

- Operand Stack을 생략하여 실제 바이트코드 실행은 구현하지 못함
- ReferenceTracker의 static 설계는 리팩토링 필요
- 멀티스레드 환경의 Stop-the-World 메커니즘 미구현

### 최종 소감

이 프로젝트는 단순히 코드를 작성하는 것을 넘어, "왜 JVM은 이렇게 설계되었을까?"라는 질문에 대한 답을 직접 찾아가는 여정이었습니다.

처음에는 막연했던 GC의 동작 원리가 이제는 손에 잡힐 듯 명확해졌고, 실제 프로덕션 환경에서 발생하는 GC 문제를 더 깊이 이해할 수 있는 기반이 마련되었습니다.
저는 이제 JVM에 대해서 잘 안다고 조금은 말할 수 있습니다. (왜냐하면 직접 만들어봤으니까요..)

스스로 매우 뿌듯하고, 이 경험이 향후 JVM 튜닝과 성능 최적화 작업에 큰 자산이 될 것이라 확신합니다.
